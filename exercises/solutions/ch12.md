# Chapter 12: Subqueries, EXISTS, and Correlated Queries — Explained Solutions

Failed-attempt existence:

```sql
SELECT o.order_number
FROM orders AS o
WHERE EXISTS (
    SELECT 1
    FROM payments AS p
    WHERE p.order_id = o.order_id
      AND p.payment_status = 'failed'
);
```

No-success existence:

```sql
SELECT o.order_number
FROM orders AS o
WHERE NOT EXISTS (
    SELECT 1
    FROM payments AS p
    WHERE p.order_id = o.order_id
      AND p.payment_status = 'successful'
);
```

An order can have a failed attempt followed by a successful one, so “has failed attempt” does not mean “has no success.”

Supplier lateness would require historical purchase orders, expected dates, actual receipt dates, and supplier references on those events. `supplier_products.lead_time_days` is a current relationship attribute, not evidence of actual historical delivery performance.
