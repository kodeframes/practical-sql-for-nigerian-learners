# Chapter 23: Capstone: School Fees and Logistics Problems — Practice Tasks

### Level A — Apply

1. Count invoices by term.
2. Count delivery attempts by status.
3. Find deliveries with no assigned driver.

### Level B — Reason

Write an invoice-balance report and explain how you preserve invoices with no successful payment.

### Level C — Professional Challenge

Design one additional table for each mini-domain that would enable a useful metric currently impossible to calculate. Explain the new grain and key relationships.

## Hands-on Lab: transfer the method to two unfamiliar schemas

For the school-fees scenario, create a small paper data dictionary before querying. Use grains such as one student, one term invoice, and one payment. Then answer: “Which students still owe money for a selected term?” Compute invoice totals and successful payments independently before comparing them at student-term grain.

For logistics, define one delivery and one delivery attempt as separate grains. A delivery may have several attempts. Answer: “Which deliveries required more than one attempt before success?” Do not count deliveries by joining attempts and then assuming one joined row still means one delivery.

### Lab verification

For school fees, choose one student and reconcile invoice amount, successful payments, and outstanding balance manually. For logistics, inspect one multi-attempt delivery in chronological order and explain which attempt establishes success.

Finally, write a short comparison: which SQL ideas transferred unchanged from MarketLedger, and which parts depended on understanding the new domain? Syntax often transfers faster than semantics. The exercise is designed to make that difference visible.
