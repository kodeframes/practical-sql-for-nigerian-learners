# Chapter 13: UNION, INTERSECT, and EXCEPT — Practice Tasks

### Level A — Apply

1. Combine customer and supplier cities with `UNION`.
2. Combine them with `UNION ALL` and compare row counts.
3. Find states shared by customers and suppliers using `INTERSECT`.

### Level B — Reason

Use `EXCEPT` to find states represented among active customers but not active suppliers. Reverse the query and explain the difference.

### Level C — Professional Challenge

You have a current-customer query and an archived-customer query with slightly different column names. Design compatible select lists for a unified export and explain which fields need explicit aliases or casts.

## Hands-on Lab: preserve duplicates deliberately

Create two compatible one-column result sets, for example customer cities and supplier cities. First combine them with `UNION ALL`:

```sql
SELECT city
FROM customers
WHERE city IS NOT NULL
UNION ALL
SELECT city
FROM suppliers
WHERE city IS NOT NULL;
```

Then replace `UNION ALL` with `UNION`. The first keeps every source row; the second removes duplicate values from the combined result.

Use `INTERSECT` to find cities present in both sets and `EXCEPT` to find customer cities that are not supplier cities.

### Lab verification

Count the rows produced by each form. Explain why the `UNION` result cannot contain more rows than `UNION ALL`. Then identify one duplicate value removed by `UNION`. Set operations are easiest to reason about when each input has the same number of columns and compatible meanings, not merely compatible data types.
