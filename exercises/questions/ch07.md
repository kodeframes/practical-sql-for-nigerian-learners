## Hands-on Lab: classify without destroying NULL meaning

Create a customer contact-quality report:

```sql
SELECT
    customer_id,
    customer_name,
    CASE
        WHEN email IS NOT NULL AND phone IS NOT NULL THEN 'email_and_phone'
        WHEN email IS NOT NULL THEN 'email_only'
        WHEN phone IS NOT NULL THEN 'phone_only'
        ELSE 'no_recorded_contact'
    END AS contact_state
FROM customers
ORDER BY customer_id;
```

The `ELSE` branch does not claim that a customer has no phone or email in real life. It says only that neither value is recorded in these columns.

Now create a display-only value with `COALESCE`:

```sql
SELECT
    customer_name,
    COALESCE(email, '[no email recorded]') AS email_display
FROM customers;
```

Do not confuse this presentation choice with data repair. The stored value remains `NULL`.

### Lab verification

Count customers by the `CASE` classification in a subquery or CTE once you are comfortable doing so. The classification counts should sum to the total number of customers. If they do not, either the categories overlap or some row was not classified as intended.
