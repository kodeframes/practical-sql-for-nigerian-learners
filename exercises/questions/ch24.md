## Hands-on Lab: perform a clean-room repository rehearsal

Create a fresh directory outside your normal project folder and pretend you are a reviewer who has never seen the work. Follow only the README. The rehearsal should let you create the database, load schema and seed data, run integrity checks, and execute at least three representative analyses without relying on undocumented local files.

Record every place where you had to use knowledge that was not written down. Those are documentation defects. Fix the README or setup scripts, delete the clean-room directory, and repeat until the process works from the documented instructions alone.

Then review commit history. Replace vague future habits such as “commit everything at the end” with small commits that explain meaningful changes: schema, seed dataset, chapter query, integrity test, documentation correction.

### Lab verification

Ask whether the repository proves five things: what problem was solved, how to reproduce it, where the data comes from, how important results were checked, and what limitations remain. A portfolio repository is strongest when a reviewer can verify the work rather than merely admire screenshots of it.
