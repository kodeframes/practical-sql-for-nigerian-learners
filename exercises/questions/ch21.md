## Hands-on Lab: separate SQL text from application values

Consider an application that searches orders by customer-supplied order number. The unsafe design concatenates text into executable SQL. The safe design sends SQL with a parameter placeholder and sends the value separately through the database driver.

Conceptually:

```text
SQL:   SELECT order_id, order_number, order_status
       FROM orders
       WHERE order_number = $1;

Value: ML-2026-0001
```

The exact placeholder style depends on the language and driver, but the principle is stable: user-controlled data is not executable SQL syntax.

Now list the minimum privileges required by a read-only reporting account that only needs selected views. It probably does not need permission to create tables, alter schemas, delete orders, or manage roles.
