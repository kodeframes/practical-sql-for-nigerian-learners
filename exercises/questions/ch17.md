# Chapter 17: INSERT, UPDATE, and DELETE Without Destroying Data — Practice Tasks

### Level A — Apply

1. Insert two rows into a practice table with an explicit column list.
2. Preview and then update one row by primary key.
3. Preview and then delete rows matching a test condition.

### Level B — Reason

Write a safe update workflow to mark all inactive practice products as active. Include the preview count and `RETURNING`.

### Level C — Professional Challenge

A colleague sends you this statement for production:

```sql
UPDATE orders
SET order_status = 'cancelled'
WHERE order_date < DATE '2025-02-01';
```

List the questions you would ask before running it. Do not execute or “fix” it until the business meaning is clear.

## Hands-on Lab: preview, modify, and receive a receipt

Use a transaction for a reversible practice update:

```sql
BEGIN;

SELECT product_id, product_name, is_active
FROM products
WHERE product_id = 12;

UPDATE products
SET is_active = TRUE
WHERE product_id = 12
RETURNING product_id, product_name, is_active;

ROLLBACK;
```

After the rollback, rerun the original `SELECT`. The row should have its original value again.

Now design a safe `DELETE` practice using a temporary table or disposable test row. The workflow must always begin with the exact `WHERE` predicate in a `SELECT`, followed by the modification and a verification step.

### Lab verification

Write down the expected affected-row count before running the modification. If `UPDATE` or `DELETE` affects a different number of rows, stop and investigate. Row count is one of the simplest operational safety checks available to you.
