## Hands-on Lab: prove referential paths explicitly

Write a diagnostic that should return no rows in a valid MarketLedger database:

```sql
SELECT
    o.order_id,
    o.branch_id
FROM orders AS o
LEFT JOIN branches AS b
    ON b.branch_id = o.branch_id
WHERE b.branch_id IS NULL;
```

The foreign-key constraint should prevent orphaned branch references, but the query is still useful as an integrity check when importing legacy data or reviewing a schema where constraints may have been disabled.

Repeat the pattern for `order_items.product_id -> products.product_id` and `employees.branch_id -> branches.branch_id`.

Then inspect the composite key in `supplier_products`. Explain why neither `supplier_id` nor `product_id` alone identifies one relationship row. The pair does.
