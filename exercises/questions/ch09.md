## Hands-on Lab: reconcile an aggregate to its source rows

Summarise orders by status:

```sql
SELECT
    order_status,
    COUNT(*) AS order_count,
    SUM(discount_amount) AS total_order_discount
FROM orders
GROUP BY order_status
ORDER BY order_status;
```

Before accepting the output, verify that the grouped counts reconcile with the source:

```sql
SELECT COUNT(*) AS all_orders
FROM orders;
```

The sum of the grouped `order_count` values must equal `all_orders` because every order has exactly one non-NULL constrained status.

Now add a `HAVING` clause that keeps only statuses with at least two orders. Notice that `WHERE` would filter individual rows before grouping, while `HAVING` filters groups after aggregation.

### Lab verification

Choose one status and independently query only those rows with `WHERE`. Compare the count and discount sum with the grouped result. This small reconciliation habit scales directly to much larger financial and operational summaries.
