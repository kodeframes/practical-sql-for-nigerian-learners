## Hands-on Lab: detect and control row multiplication

Start at order grain and count lines per order:

```sql
SELECT
    o.order_id,
    o.order_number,
    COUNT(oi.order_item_id) AS line_count
FROM orders AS o
JOIN order_items AS oi
    ON oi.order_id = o.order_id
GROUP BY o.order_id, o.order_number
ORDER BY o.order_id;
```

Now join payments as well. An order with two order items and two payment rows can produce four joined rows. That is a correct relational result, but it is dangerous if you sum line values or payment amounts without controlling grain.

The safer approach is often to aggregate each one-to-many child independently before joining:

```sql
WITH line_totals AS (
    SELECT order_id, SUM(quantity * unit_price - discount_amount) AS line_total
    FROM order_items
    GROUP BY order_id
), payment_totals AS (
    SELECT order_id, SUM(amount) AS paid_successfully
    FROM payments
    WHERE payment_status = 'successful'
    GROUP BY order_id
)
SELECT o.order_number, lt.line_total, pt.paid_successfully
FROM orders AS o
LEFT JOIN line_totals AS lt ON lt.order_id = o.order_id
LEFT JOIN payment_totals AS pt ON pt.order_id = o.order_id;
```

### Lab verification

Pick one order with multiple lines or payments and calculate both totals manually. Then prove the pre-aggregated query returns one row per order.
