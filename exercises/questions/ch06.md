## Hands-on Lab: make a top-N result reproducible

A request for “the five most expensive active products” contains three distinct operations: restrict the population, define the ranking metric, and choose a deterministic tie-breaker.

```sql
SELECT
    sku,
    product_name,
    unit_price
FROM products
WHERE is_active = TRUE
ORDER BY unit_price DESC, product_id ASC
LIMIT 5;
```

The secondary `product_id` ordering matters when two products have the same price. Without a tie-breaker, two executions may both be valid while returning tied rows in a different order.

Now compare that query with:

```sql
SELECT DISTINCT city
FROM customers
WHERE city IS NOT NULL
ORDER BY city;
```

`DISTINCT` changes the output grain from one row per customer to one row per distinct city value. `LIMIT` does not change grain; it only restricts how many already-ordered rows are returned.

### Lab verification

State the output grain of both queries. Then remove `ORDER BY` from the first query and explain why the phrase “top five” has become semantically unsupported even though PostgreSQL will still return five rows.
