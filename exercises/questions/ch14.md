## Hands-on Lab: make intermediate grain visible with CTEs

Build completed-order totals in stages:

```sql
WITH line_totals AS (
    SELECT
        order_id,
        SUM(quantity * unit_price - discount_amount) AS line_total
    FROM order_items
    GROUP BY order_id
), completed_orders AS (
    SELECT
        o.order_id,
        o.branch_id,
        o.order_date,
        lt.line_total - o.discount_amount AS order_total
    FROM orders AS o
    JOIN line_totals AS lt
        ON lt.order_id = o.order_id
    WHERE o.order_status = 'completed'
)
SELECT
    branch_id,
    SUM(order_total) AS branch_value
FROM completed_orders
GROUP BY branch_id
ORDER BY branch_id;
```

The value of the CTEs here is explanatory structure. `line_totals` has one row per order; `completed_orders` also has one row per completed order; only the final query changes grain to one row per branch.

### Lab verification

Run each CTE body as a standalone query while developing. Confirm its grain before adding the next stage. Do not claim the CTE makes the query faster; inspect a plan before making performance statements.
