## Hands-on Lab: compare ranking and aggregation

Rank products within category without collapsing the product rows:

```sql
SELECT
    category_id,
    product_id,
    product_name,
    unit_price,
    RANK() OVER (
        PARTITION BY category_id
        ORDER BY unit_price DESC
    ) AS price_rank
FROM products
WHERE is_active = TRUE
ORDER BY category_id, price_rank, product_id;
```

A `GROUP BY category_id` query could tell you the maximum price per category, but it would not retain every product row. The window function does.

Now calculate a running total of successful payment amounts ordered by payment timestamp:

```sql
SELECT
    payment_id,
    payment_date,
    amount,
    SUM(amount) OVER (
        ORDER BY payment_date, payment_id
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_paid
FROM payments
WHERE payment_status = 'successful'
ORDER BY payment_date, payment_id;
```

### Lab verification

Manually add the first three successful payments and compare with the third running-total row. The explicit `ROWS` frame makes the intended cumulative behaviour clear even when ordering values tie.
